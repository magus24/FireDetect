# FireDetect — автономный противопожарный дрон (Edge AI MVP)

**Детекция огня и дыма в реальном времени на edge-GPU с замкнутым контуром от пикселей до сброса капсулы.**

🇷🇺 Русский · [🇬🇧 English version](README.md)

> **Статус:** рабочий MVP / proof of concept. Это инженерный демонстратор, а **не** сертифицированная система пожаротушения.

---

## О проекте

FireDetect — прототип подсистемы восприятия и полезной нагрузки автономного противопожарного дрона. Поток с камеры обрабатывается обученной моделью **YOLOv8** на GPU, и при подтверждении огня или дыма с достаточной уверенностью приложение прогоняет конечный автомат и отправляет один байт по UART на **ESP32**, который приводит в действие сервопривод механизма сброса капсулы.

Проект можно запустить и **без железа**: если ESP32 или COM-порт недоступны, приложение продолжает работать и логирует срабатывание в режиме симуляции. Встроенный **настольный демо-режим** позволяет безопасно проверить всю цепочку «наведение → сброс» в помещении, используя телефон, кружку или бутылку вместо открытого огня.

```
 ┌──────────────────────┐     ┌──────────────────────┐     ┌──────────────────────┐
 │  Камера (OpenCV)     │ ──► │  YOLOv8n fire/smoke  │ ──► │  Порог уверенности   │
 │  MSMF / DirectShow   │     │  FP16 · CUDA         │     │  + кулдаун           │
 └──────────────────────┘     └──────────────────────┘     └──────────┬───────────┘
                                                                      │ 'D' по UART
                                                                      ▼
 ┌──────────────────────┐     ┌──────────────────────┐     ┌──────────────────────┐
 │  Капсула сброшена    │ ◄── │  Серво 0° → 90° (3с) │ ◄── │  ESP32 (неблокирующий│
 │  из отсека           │     │  GPIO 13 · PWM 50 Гц │     │  конечный автомат)   │
 └──────────────────────┘     └──────────────────────┘     └──────────────────────┘
```

## Ключевые особенности

- **Своя 2-классовая модель** — веса YOLOv8n для классов `smoke` и `fire` лежат в [`models/fire_yolov8n.pt`](models/fire_yolov8n.pt), поэтому репозиторий работает сразу после клонирования.
- **Оптимизация под edge** — автоопределение CUDA, FP16 на GPU, прогрев модели и откат на CPU (`--cpu`).
- **Замкнутый контур** — детекция → порог уверенности → кулдаун → команда `'D'` по UART → физический сброс сервоприводом.
- **Отказоустойчивость** — отсутствие камеры, порта или модели не роняет приложение: оно переходит в явно обозначенный режим симуляции/ожидания.
- **Тактический HUD** — рамка захвата цели, FPS и задержка инференса, индикатор угла серво, бейдж режима и состояние системы.
- **Демо-режим** — переключает целевые классы на объекты COCO (телефон, кружка, бутылка) для безопасных тестов за столом; включается клавишей `M`.
- **Надёжная работа с камерами Windows** — перебор DirectShow → default → MSMF и горячая смена индекса камеры клавишей `C`.
- **Безопасность на уровне прошивки** — неблокирующий автомат, игнорирование повторных команд сброса и аварийный сброс `R`.

## Быстрый запуск (Windows)

### 1. Установка зависимостей

Дважды кликните **`install_dependencies.bat`** или выполните:

```bat
install_dependencies.bat
```

Скрипт проверит Python, создаст изолированное окружение `venv`, поставит PyTorch с CUDA 12.1 (с откатом на CPU) и зависимости из `requirements.txt`.

### 2. Запуск

Дважды кликните **`start_app.bat`** или выполните:

```bat
start_app.bat
```

Без аргументов приложение стартует в **демо-режиме**, чтобы его можно было сразу проверить за столом. Все переданные аргументы пробрасываются в `src/main.py`.

### Ручной запуск (любая ОС)

```bash
python -m venv venv
# Windows: venv\Scripts\activate
source venv/bin/activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121  # опционально, GPU-сборка
pip install -r requirements.txt
python src/main.py --demo
```

> На Linux/macOS `.bat`-файлы не используются — запускайте вручную. Звуковые сигналы доступны только в Windows (`winsound`), на других ОС они пропускаются.

### Параметры CLI

| Флаг | По умолчанию | Описание |
| --- | --- | --- |
| `--model` | `models/fire_yolov8n.pt` | Путь к весам YOLOv8 |
| `--port` | `COM3` | COM-порт ESP32 (при отсутствии — симуляция) |
| `--baud` | `115200` | Скорость UART |
| `--camera` | `0` | Начальный индекс камеры |
| `--conf` | `0.75` | Порог уверенности для подтверждённой цели |
| `--cooldown` | `5.0` | Интервал между сбросами, секунды |
| `--demo` | выкл. | Старт в настольном демо-режиме |
| `--cpu` | выкл. | Принудительный инференс на CPU |

### Горячие клавиши

| Клавиша | Действие |
| --- | --- |
| `SPACE` | Ручной тест сброса (серво 90°, удержание 3 с, возврат в 0°) |
| `C` | Переключение камеры `0 → 1 → 2 → 0` |
| `M` / `T` | Переключение демо-режима (объекты COCO ↔ только огонь) |
| `S` | Вкл./выкл. звук |
| `H` | Показать/скрыть подсказку по управлению |
| `Q` / `ESC` | Выход |

## Аппаратная часть

| Компонент | Рекомендуемая модель | Примечание |
| --- | --- | --- |
| Вычисления | Ноутбук с NVIDIA GPU (разработка на RTX 3070 Ti) | На CPU тоже работает, но FPS ниже |
| Камера | Встроенная или USB-камера | Индекс меняется на лету |
| Микроконтроллер | ESP32 Dev Module / ESP32-WROOM-32 | Любая плата с UART по USB |
| Привод | Сервопривод SG90 / MG995 / MG996R | Открывает отсек с капсулой |
| Питание | Внешний BEC на 5 В для серво | **Не** питайте серво от 3.3 В ESP32 |
| Полезная нагрузка | Капсула и механизм сброса | Механика в репозиторий не входит |

**Подключение:** сигнал серво → **GPIO 13**, питание серво → внешние 5 В, земля серво и ESP32 → **общая земля**. Светодиод статуса → GPIO 2.

### Прошивка ESP32

1. Откройте [`firmware/drop_capsule/drop_capsule.ino`](firmware/drop_capsule/drop_capsule.ino) в Arduino IDE.
2. Установите библиотеку **ESP32Servo** (менеджер библиотек, автор Kevin Harrington) и пакет плат ESP32.
3. Выберите плату и порт, прошейте.
4. Закройте Serial Monitor в Arduino IDE перед запуском Python-приложения — порт монопольный.

### Протокол UART

| Байт | Действие |
| --- | --- |
| `D` / `d` | Сброс: серво в 90°, удержание 3 с, возврат в 0° |
| `R` / `r` | Аварийный сброс: немедленно закрыть и заблокировать |
| `S` / `s` | Запросить текущее состояние |
| `T` / `t` | Диагностический цикл сброса |

Прошивка подтверждает команды и отклоняет новый сброс, пока предыдущий цикл не завершён. Тайминги построены на `millis()`, а не на `delay()`, поэтому ESP32 остаётся отзывчивым.

## Как это работает

1. **Захват** — `LaptopCameraManager` перебирает бэкенды и индексы, проверяет реальный кадр и запрашивает 1280×720 с буфером на один кадр.
2. **Детекция** — каждый кадр уходит в YOLOv8 с `conf=0.35` для сопровождения; выбирается цель с максимальной уверенностью.
3. **Подтверждение** — цель считается захваченной только при `--conf` (по умолчанию 0.75). Ниже порога HUD показывает её как сопровождаемую, но сброс не выполняется.
4. **Блокировка** — сброс разрешён только после истечения кулдауна, чтобы избежать серии срабатываний.
5. **Срабатывание** — в порт пишется `'D'`. Без железа событие логируется и отображается как симулированный угол 90°.
6. **Телеметрия** — FPS, задержка инференса, вычислительное устройство, индекс камеры, состояние связи и режим миссии выводятся на HUD.

### Принятые решения

- **Таймингом управляет MCU, а не ПК.** Удержание 3 секунды обеспечивает ESP32, поэтому сбой USB или падение приложения не оставит отсек открытым. Python-сторона работает по принципу «отправил и забыл».
- **Симуляция — полноценный режим, а не ошибка.** Благодаря ей проект можно проверить и показать на любой машине без дрона.
- **Разные пороги для сопровождения и срабатывания.** 0.35 стабилизирует рамку, 0.75 защищает от сброса по одному шумному кадру.
- **Демо-режим явно виден в HUD.** Бейдж режима и строка состояния не дают перепутать тест на кружке с реальной детекцией огня.

## О модели

- Архитектура: **YOLOv8n**, 2 класса — `0: smoke`, `1: fire`.
- Веса: [`models/fire_yolov8n.pt`](models/fire_yolov8n.pt) (≈6 МБ), включены для воспроизводимости.
- Инференс: вход 640 px, FP16 на CUDA, низкий порог для сопровождения и высокий для срабатывания.
- Если `models/fire_yolov8n.pt` отсутствует, приложение скачает стандартную COCO-модель `yolov8n.pt` и автоматически включит демо-режим.
- Датасет и ноутбук обучения в репозиторий не входят; модель обучена на датасете детекции огня и дыма и предназначена для демонстрации, а не для задач, связанных с безопасностью жизни.

**Почему модели нет в `requirements.txt`?** `requirements.txt` содержит только Python-пакеты — веса моделей не устанавливаются через pip. Обученная fire-модель лежит прямо в репозитории: `models/fire_yolov8n.pt`, поэтому после `git clone` ничего дополнительно скачивать не нужно. Стандартная COCO-модель `yolov8n.pt` намеренно не закоммичена: Ultralytics скачает её автоматически, если кастомные веса отсутствуют.

## Ограничения и планы

**Известные ограничения**

- Детекция по одному кадру: нет временного сглаживания, трекинга и отличия дыма от пара.
- Нет геометрии наведения: сброс происходит при подтверждении цели, а не при фактическом совмещении дрона с очагом.
- Инструменты ориентированы на Windows; звук доступен только там.
- Модель не проверялась по формальному пожарному бенчмарку.
- Автотестов пока нет.

**Планы**

- [ ] Трекинг ByteTrack/BoT-SORT и подтверждение по N кадрам для снижения ложных срабатываний
- [ ] Оценка пеленга и дистанции до цели для реального прицеливания
- [ ] Интеграция MAVLink (ArduPilot/PX4) вместо настольного контура
- [ ] Логи миссий и инструмент постполётного разбора
- [ ] Юнит-тесты автомата, кулдауна и протокола UART
- [ ] Кроссплатформенные лаунчеры и контейнеризованный инференс

## Предупреждение о безопасности

Проект создан как исследовательский прототип и портфолио-демонстратор. Его нельзя использовать вместо сертифицированного оборудования обнаружения и тушения пожара. Не тестируйте на неконтролируемом огне: используйте встроенный демо-режим или разрешённый контролируемый стенд со средствами пожаротушения.
